# Соглашения

## Размер и границы

- Размер файла — запах, а не правило: `.ts` делим по реальному шву (сцена/подсистема/этап,
  а не по 20 строк). `pnpm check:structure` только перечисляет модули крупнее 500 строк —
  повод посмотреть, не делает ли файл три работы сразу.
- Большой класс делим по реальному шву: сцена/подсистема/этап, а не по 20 строк.
- Данные (`fish/`, `world/`, `texts`, `areas`, `config`) не импортируют UI.
- Экраны и UI импортируют `GameContext`, а не класс `Game`.
- Runtime-циклы импортов запрещены. Type-only циклы тоже лучше не заводить, но
  проверка игнорирует `import type`.

## Код

- Строгий TypeScript; `noUnusedLocals`/`noUnusedParameters` включены.
- Комментарии — по делу, на английском (как в существующем коде); пользовательские
  строки — на русском в `texts.ts`.
- Никакого мёртвого кода и «на будущее». Неиспользуемый export удаляем.
- Форматирование — Prettier через ESLint (`pnpm lint`).
- Публичный API — `src/lib/fishing/index.ts`. Внутренние модули не обещают
  стабильность.
- Не переименовывать id водоёмов и не менять схему прогресса без миграции.

## Документация

- `AGENTS.md` — короткая точка входа, только необходимое и ссылки.
- `docs/` — подробности; при изменении границ модулей обновляйте `modules.md`.
- Ссылки в `AGENTS.md`/`docs` проверяет `pnpm check:structure`.
